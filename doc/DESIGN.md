# org-seq 发行版设计

状态：2026-11-12 起草，同日两次修订。第一至第五节描述已经实现的行为，第六节是尚未实现的部分，第七节是需要作者确认的取舍。

## 一、定位与已定的方向

org-seq 是一个面向个人知识管理的 Emacs 发行版：部署一次就能用，笔记放在哪里、怎么备份、怎么跨设备，都由发行版决定并且可以查看，使用者不需要为此写 Elisp，也不会在启动时被提问。设计参照三个产品：Doom Emacs（发行版核心与功能模块分开，使用者配置有固定位置，命令行负责维护），Tana（一切都是节点，类型带字段并可继承，日记是默认入口），Notion（数据库等于某类节点加视图，视图只是查询加布局）。

规则：

1. 位置固定。笔记库只有一个位置，不让使用者选择目录。
2. 归属清楚。Emacs 目录里的每个文件只属于一个所有者，升级只动发行版自己的文件。
3. 进出都是复制。笔记库之外的内容通过导入、导出、快照、同步进出，前三者从不修改来源，也从不覆盖笔记库里已有的文件。
4. Org 文本是唯一权威。索引、视图、数据库文件都可以删掉重建。

作者在 2026-11-12 定下的三件事：

- org-roam 先降为可选，随后整体移除（2026-11-12）；org-seq 自己维护节点索引。
- 源码按发行版核心、笔记内核、功能模块重排目录。
- 平台优先级：Linux 为 P0，每项改动都在 Linux 上验证；Windows 和 macOS 为 P1，脚本保持一致但不阻塞 Linux 上的工作。

作者在 2026-11-13 定下的笔记库分区：org-seq 直接对标 Notion，笔记库仍是 Inbox + PARA + AI System 三部分。

| 分区 | 对标 | 现有位置 | 职责 |
| --- | --- | --- | --- |
| Inbox | Tana | `00_Inbox/`（`daily/`、`capture/`；0.2.0 之前叫 `00_Roam/`） | 暂存区。日记、草稿、随手采集，按 org-roam 的方式组织：一个想法一个节点，靠链接和反向链接联系，录入时不要求分类和填字段 |
| PARA | Notion | `10_Outputs/`（项目）、`20_Practice/`（领域）、`30_Library/`（资源）、`40_Archives/`（归档） | 确认保留的内容。类型即数据库，带字段、关系和视图 |
| AI System | 现在的 AI 记忆工具 | `50_AI/`，目前只有 `purpose.org`、`schema.org`、`overview.org` 三个上下文文件 | 各 AI 共用的长期记忆、指令和 Skills，通过命令行和 MCP 读写 |

这个决定带来的后果（实现状态见第六节）：

- Inbox 里的节点是待处理的。从 Inbox 转入 PARA 是一个明确的动作，由使用者发起，转入时才补类型和字段。
- PARA 各层都要能当数据库用，所以索引收录所有层（已实现）。记录带 `:layer`，视图默认不显示归档层，过滤条件里写了 `(layer ...)` 时以它为准。
- 目录跟着分区改名（作者 2026-11-13 决定）：`00_Roam/` 改为 `00_Inbox/`，新增 `50_AI/`。旧笔记库不会在启动时被改动，仍从旧名字工作，由 `orgseq migrate --yes` 先做快照再改名；自检项“Library layout”提示尚未迁移。
- 长期目标是由 org-seq 取代 Notion 和 Tana（作者 2026-11-13 确认）。
- AI System 需要一个固定位置和一组类型，并且要有按客户端区分的读写权限。

## 二、目录归属

源码仓库和部署后的 Emacs 目录使用同一套布局：

```
early-init.el  init.el  ec
core/        发行版核心：平台修正、包管理、自检、更新、命令行（orgseq-cli.el）
kernel/      笔记内核，无界面：orgseq-paths.el（路径）、orgseq-index.el（节点索引）、orgseq-note.el（新建笔记、日记文件）
modules/     功能模块，按领域分组，文件名仍是 init-*.el
  ui/        主题与排版、仪表盘、工作区、弹窗、鼠标、终端界面、首次启动引导页
  editor/    evil、按键约定、补全、输入法
  notes/     Org、采集与日记、GTD、节点类型、视图、命令面板、存储与同步
  tools/     终端、AI、文件管理
  lang/      Python、Markdown、其他语言
packages/    可独立发布的子项目
bin/         orgseq 命令行启动器
user/        使用者自己的文件（只存在于部署后的目录）
notes/       笔记库（只存在于部署后的目录）
private/     隔离区（只存在于部署后的目录，第一次使用时创建）
```

| 所有者 | 路径 | 谁会写它 | 丢失后的恢复方式 |
|--------|------|----------|------------------|
| 发行版 | `early-init.el`、`init.el`、`ec`、`core/`、`kernel/`、`modules/`、`packages/`、`bin/` | 只有部署脚本 | 重新部署 |
| 使用者 | `user/custom.el`、`user/modules.el`、`user/config.el` | 使用者和 Customize | 部署备份里有一份 |
| 笔记库 | `notes/` | 使用者、导入、同步 | 快照或云端 |
| 隔离区 | `private/` | 只有使用者，以及带 `--private` 的 Notion 导入 | 隔离区自己的本地副本（`~/.local/share/org-seq/snapshots-private/`） |
| 设备状态 | `.cache/`、`elpa/`、`eln-cache/`、`package-snapshots/` | Emacs 运行时 | 可重建，不需要备份 |
| 快照 | Emacs 目录之外，Linux 为 `~/.local/share/org-seq/snapshots/` | 只有快照命令 | 本身就是副本 |

`user/` 的三个文件：`modules.el` 在模块加载前读取，用 `my/init-disabled-modules` 关掉不需要的模块，用 `my/init-user-modules` 登记放在 `user/` 里的自己的模块；`config.el` 在所有模块之后加载，放个人设置；`custom.el` 是 Customize 的保存位置。部署脚本只在这些文件不存在时创建示例，旧版本留在顶层的 `custom.el` 会被移进来一次。

模块的加载顺序由依赖计算：`my/init-module-requires` 记录每个模块依赖谁，启动时做一次稳定的拓扑排序，`init-doctor` 固定在最前、`init-evil` 固定在最后。使用者的模块走同一套排序和同一个带保护的加载器，依赖缺失时跳过并给出警告。`M-x my/init-report` 显示每个模块的来源、位置和跳过原因。

部署脚本只替换“发行版”一行里的文件。`deploy.sh` 的备份包含被替换的文件和 `user/`（几 MB），需要整目录备份时用 `--full-backup`。旧布局的 `lisp/` 在备份后删除。部署时在目标目录写下 `.org-seq-source`（来源路径、远端地址、分支、提交），之后 `orgseq upgrade` 据此自升级：来源是本地检出时原样使用、不改动它，来源是远端地址时克隆到 `.cache/source` 再部署；`orgseq upgrade --check` 只报告是否有新版本。版本号来自仓库根目录的 `VERSION` 文件。

笔记库内部的结构（`00_Inbox/`、PARA 各层、`50_AI/`、`.orgseq/`）见 [NOTES_ARCHITECTURE.md](NOTES_ARCHITECTURE.md)，这里不重复。

## 三、笔记内核与索引

内核是 `kernel/` 下不带界面的代码，批处理 Emacs 不加载任何模块也能使用它。目前有三个文件：`orgseq-paths.el` 定义所有笔记库路径，`orgseq-index.el` 是节点索引，`orgseq-note.el` 是唯一写新笔记文件的地方（交互采集和命令行共用），并拒绝把笔记写到笔记库之外。

节点是带 Org ID 的文件或标题。索引把 Org 文件里的节点抄成一份可以随时丢弃的副本：

- 存储用 Emacs 内置的 SQLite，不依赖 emacsql 或 org-roam。文件在 `.cache/index-<哈希>.db`，每个笔记库路径一个，验证时指向临时笔记库不会改写真实索引。
- 解析是对文件文本的直接扫描，只认标题、属性抽屉、计划行、`#+title`、`#+filetags` 和 id 链接，不启动 `org-mode`。
- 刷新是增量的：比较文件的修改时间和大小，只重读有变化的文件。不依赖文件监视，所以同步、git 或其他程序做的修改也会被发现。在 Emacs 里保存笔记时立即重读该文件。
- 全文检索用 FTS5 的三元组分词，按子串匹配，中文不需要分词；每个节点只收录它自己的文字，不包含嵌套在里面的其他节点。
- 图形界面、守护进程和命令行打开同一个文件，写入由 SQLite 串行化，每个写入方从同样的文件得出同样的行。

读取接口只有四个：`my/index-records`（全部节点）、`my/index-node`（按 ID）、`my/index-links`（id 链接）、`my/index-search`（全文检索）。视图、节点表、仪表盘查询块、命令行、MCP 和 AI 概览都只通过它们读节点。写入仍然只有一条路径：`my/node-call-at-id` 修改 Org 文件，然后让索引重读该文件。

索引范围是笔记库里除隐藏目录和同步冲突副本之外的 `.org` 文件，包括资源层和归档层。

org-roam 不再是 org-seq 的一部分（2026-11-12 移除，也没有可选模块机制）。采集（`my/note-capture`，兼容 `.orgseq/capture-templates.el` 里原 org-roam-capture 格式模板的常用写法）、日记命令、查找节点、插入链接、反向链接与正向链接列表、id 链接跳转都由内核和 `init-capture`、`init-nodes` 提供。图谱界面（org-roam-ui）和 consult-org-roam 随之取消。

交互层在 `init-palette`：`SPC k` 打开命令面板（节点、`#类型` 新建、`@视图`、`>命令` 在一个补全界面里）；Org 缓冲区行首输入 `/` 弹出插入菜单；带类型的文件级节点在标题下显示字段面板（只是显示，属性抽屉仍是数据来源）。首次启动时 `init-welcome` 显示一次引导页，列出笔记库位置、下一步和自检结果，之后用 `SPC h w` 打开。

## 四、存储模型

笔记库是 `notes/` 下的普通 Org 文件，Org 文本是唯一权威，节点索引（`.cache/` 下）是可以重建的索引。

内容进出笔记库的四条通道：

| 通道 | 方向 | 触发 | 会覆盖已有文件吗 | 会删除文件吗 |
|------|------|------|------------------|--------------|
| 导入 `my/storage-import` | 外部文件夹到笔记库 | 手动 | 不会 | 不会 |
| 导出 `my/storage-export` | 笔记库到外部文件夹 | 手动 | 不会，总是新建带日期的文件夹 | 不会 |
| 恢复 `my/storage-restore` | 快照到笔记库 | 手动，需确认 | 会，笔记库变成与所选快照一致 | 会，删除快照里没有的文件；恢复前先做一份快照以便撤销 |
| 快照 `my/storage-snapshot` | 笔记库到快照目录 | 每天自动一次，导入前，全量同步前，或手动 | 不会 | 只删除超出保留份数的旧快照 |
| 同步 `my/sync-now` | 笔记库与云端双向 | 启动后和定时，或手动 | 会，较新的一份生效，另一份留作 `.conflict` 副本 | 会，一端删除后另一端跟着删除 |

同步是唯一会自动覆盖和删除的通道，所以快照独立于同步存在：误删或错误合并之后，可以从快照目录找回当天之前的版本。

导入的落点规则：

- 来源带有 `00_Inbox/`、`00_Roam/` 或 `.orgseq/`，说明它本身是一个 org-seq 笔记库，按层合并；旧布局的 `00_Roam/` 并入 Inbox 层，其中的 AI 上下文文件放进 `50_AI/`。
- 其他文件夹整体放进 `30_Library/<文件夹名>/`，作为参考资料，之后再由使用者整理成节点。
- 来源与笔记库有重叠时拒绝执行。

启动时的行为：创建缺失的笔记库目录，到期时做一次快照，配置了远端时做一次同步。发现未导入的 `~/NoteHQ/` 时只在回显区提示一次，不弹对话框；这条信息之后一直显示在 `my/storage-status` 和 `orgseq info` 里。

## 五、数据保护

一份笔记最多存在于三个地方：笔记库、本机快照、云端远端。

| 情况 | 能恢复的来源 |
|------|--------------|
| 删除或重装了 `~/.emacs.d` | 快照目录，云端 |
| 同步把误删带到了本机 | 快照目录 |
| 导入或合并的结果不对 | 操作前自动生成的快照 |
| 磁盘损坏或设备丢失 | 只有云端 |

最后一行是这套方案的边界：快照和笔记库在同一块磁盘上，没有配置同步时，磁盘损坏会同时丢掉两者。`M-x my/doctor` 的 “Library copies” 检查在既没有远端也没有快照时给出警告，但有快照而没有远端时判为通过。

查看状态的入口是同一个函数 `my/storage-info`：图形界面 `SPC n S t`，命令行 `orgseq info`，自检 `orgseq doctor`。

      - 没有做的：加密。文件是明文，拿到路径的程序都能读，整盘备份和 `deploy.sh --full-backup` 也会带上它。
   5. （已完成；2026-11-13 用一份真实的全量导出跑通：2681 页，咨询分区进隔离区）Notion 导入（`modules/notes/init-import.el`）：`orgseq import-notion DIR`、`SPC n S n`。读取解压后的“Markdown & CSV”导出目录，只读不改。
      - 每页一篇笔记，属性 `NOTION_ID` 记录来源页；再次运行跳过已导入的页，不覆盖。
      - 正文由内置转换器转成 Org（标题、列表、复选框、引用、代码块、表格、强调、链接、图片），不依赖 pandoc。
      - 页面之间的链接转成 id 链接（同一批或之前导入过的页）；导出范围之外的页只保留文字。附件复制到笔记旁的 `assets/`。
      - 数据库的行：标题下的“属性: 值”转成 Org 属性，只认该数据库 CSV 里的列名，普通正文不会被误读。日期转成 `YYYY-MM-DD`，复选框转成 yes/no，关联转成 id 链接。
      - 类型由使用者决定：`--db-type 数据库名=类型` 给某个数据库的行套用 `types.org` 里已有的类型，`--type T` 套用到所有页，`--map 属性=字段` 改名；导入不会新建类型，预览里列出类型没有对应字段的属性（仍会写入）。
      - 建议整个导出一次导完，每个数据库各用一个 `--db-type`。分批导入时，先导的那批里指向“还没导的页”的链接只能保留文字，之后不会补上。
      - 落点：`--layer`，否则类型的 `TYPE_LAYER`，否则 `30_Library/notion/`。`--private` 写入隔离区，页面之间用文件链接。
      - 不带 `--yes` 只预览。写入前先做快照。
      - 路由（真实导出之后加的）：`--route 路径=去向` 把导出里某个路径（按标题，不含 id）以下的页面送到某一层、隔离区或不导入，去向写作 `area`、`ai/Skills`、`private/x`、`skip`；最长的路径前缀生效，前缀以下的文件夹原样保留。Notion 的页面树因此变成笔记库的目录树，而不是全堆进一个 `notion/` 文件夹。同一次运行可以同时写笔记库和隔离区。

      - 数据库变成一篇笔记：每个数据库有一篇同名笔记，正文是一个 `orgseq-view` 块，用新增的过滤条件 `(folder "相对路径")` 列出该文件夹里的行。指向数据库的链接指向这篇笔记。隔离区没有索引，那里的数据库笔记是一份文件链接清单。

      - 真实导出与最初假设的差别，都已处理：数据库文件名是 `名称 <id>_all.csv`；行所在的文件夹不带 id；页面里的内嵌数据库叫 `页面 <id>_数据库 <id>_all.csv`，几个数据库的行可以在同一个文件夹里（按属性行判断归属）；重名文件夹带截断的 id（`Memories 4108-63d6`）；上传的文件在 `attachments/` 下，其中的 `.md`、`.csv` 不是页面；内嵌视图在链接后面留下 `sort:`、`filters:` 行（丢弃）；`Untitled` 链接文字换成目标页的标题。

## 七、需要确认的取舍

以下是实现时做的选择，可以改：

- 快照放在 Emacs 目录之外。好处是删掉 `~/.emacs.d` 不会连快照一起丢；代价是“所有东西都在软件目录里”这一点有了一个例外。
- 快照保留 10 份，每天最多自动做 1 份，并且只在笔记库有改动的日子做。
- 普通文件夹导入到 `30_Library/`，而不是 `00_Inbox/`。理由是没有 Org ID 的文件不是节点，放进 Inbox 会让那一层变乱。
- 导入从不覆盖。同名文件以笔记库里的为准，来源里的版本被跳过，不生成冲突副本。
- 笔记库位置仍然是一个可定制变量（`my/note-home`），只是不在任何界面里要求设置。
- `dashboards/` 仍放在 Inbox 层下面。它存的是查询定义，不是待处理内容，放在这里只是因为没有动它。
- 索引现在收录 `30_Library/` 里所有带 Org ID 的文件。导入进来的普通文件夹里没有 Org ID 的文件仍然不是节点，不会出现在视图和检索里，直到加上 ID。
- 隔离区放在笔记库之外、不同步、不加密。好处是不需要维护排除清单，新功能默认就碰不到它；代价是它只在这一台设备上，换设备要自己拷贝，而且明文存放。
- Notion 导入只接受导出目录，不直接连 Notion 的接口，所以不需要保存任何令牌。
- 模块文件保留 `init-*.el` 的名字，只移动了目录，没有改成 Doom 那样每个模块一个子目录。
