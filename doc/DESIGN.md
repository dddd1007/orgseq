# org-seq 发行版设计

状态：2026-11-12 起草并修订。第一至第五节描述已经实现的行为，第六节是尚未实现的部分，第七节是需要作者确认的取舍。

## 一、定位与已定的方向

org-seq 是一个面向个人知识管理的 Emacs 发行版：部署一次就能用，笔记放在哪里、怎么备份、怎么跨设备，都由发行版决定并且可以查看，使用者不需要为此写 Elisp，也不会在启动时被提问。设计参照三个产品：Doom Emacs（发行版核心与功能模块分开，使用者配置有固定位置，命令行负责维护），Tana（一切都是节点，类型带字段并可继承，日记是默认入口），Notion（数据库等于某类节点加视图，视图只是查询加布局）。

规则：

1. 位置固定。笔记库只有一个位置，不让使用者选择目录。
2. 归属清楚。Emacs 目录里的每个文件只属于一个所有者，升级只动发行版自己的文件。
3. 进出都是复制。笔记库之外的内容通过导入、导出、快照、同步进出，前三者从不修改来源，也从不覆盖笔记库里已有的文件。
4. Org 文本是唯一权威。索引、视图、数据库文件都可以删掉重建。

作者在 2026-11-12 定下的三件事：

- org-roam 降为可选，org-seq 自己维护节点索引。
- 源码按发行版核心、笔记内核、功能模块重排目录。
- 平台优先级：Linux 为 P0，每项改动都在 Linux 上验证；Windows 和 macOS 为 P1，脚本保持一致但不阻塞 Linux 上的工作。

## 二、目录归属

源码仓库和部署后的 Emacs 目录使用同一套布局：

```
early-init.el  init.el  ec
core/        发行版核心：平台修正、包管理、自检、更新、命令行（orgseq-cli.el）
kernel/      笔记内核，无界面：orgseq-paths.el（路径）、orgseq-index.el（节点索引）
modules/     功能模块，按领域分组，文件名仍是 init-*.el
  ui/        主题与排版、仪表盘、工作区、弹窗、鼠标、终端界面
  editor/    evil、按键约定、补全、输入法
  notes/     Org、org-roam、GTD、日记、节点类型、视图、存储与同步
  tools/     终端、AI、文件管理
  lang/      Python、Markdown、其他语言
packages/    可独立发布的子项目
bin/         orgseq 命令行启动器
user/        使用者自己的文件（只存在于部署后的目录）
notes/       笔记库（只存在于部署后的目录）
```

| 所有者 | 路径 | 谁会写它 | 丢失后的恢复方式 |
|--------|------|----------|------------------|
| 发行版 | `early-init.el`、`init.el`、`ec`、`core/`、`kernel/`、`modules/`、`packages/`、`bin/` | 只有部署脚本 | 重新部署 |
| 使用者 | `user/custom.el`、`user/modules.el`、`user/config.el` | 使用者和 Customize | 部署备份里有一份 |
| 笔记库 | `notes/` | 使用者、导入、同步 | 快照或云端 |
| 设备状态 | `.cache/`、`elpa/`、`eln-cache/`、`package-snapshots/` | Emacs 运行时 | 可重建，不需要备份 |
| 快照 | Emacs 目录之外，Linux 为 `~/.local/share/org-seq/snapshots/` | 只有快照命令 | 本身就是副本 |

`user/` 的三个文件：`modules.el` 在模块加载前读取，用 `my/init-disabled-modules` 关掉不需要的模块；`config.el` 在所有模块之后加载，放个人设置；`custom.el` 是 Customize 的保存位置。部署脚本只在这些文件不存在时创建示例，旧版本留在顶层的 `custom.el` 会被移进来一次。

部署脚本只替换“发行版”一行里的文件。`deploy.sh` 的备份包含被替换的文件和 `user/`（几 MB），需要整目录备份时用 `--full-backup`。旧布局的 `lisp/` 在备份后删除。

笔记库内部的结构（`00_Roam/`、PARA 各层、`.orgseq/`）见 [NOTES_ARCHITECTURE.md](NOTES_ARCHITECTURE.md)，这里不重复。

## 三、笔记内核与索引

内核是 `kernel/` 下不带界面的代码，批处理 Emacs 不加载任何模块也能使用它。目前有两个文件：`orgseq-paths.el` 定义所有笔记库路径，`orgseq-index.el` 是节点索引。

节点是带 Org ID 的文件或标题。索引把 Org 文件里的节点抄成一份可以随时丢弃的副本：

- 存储用 Emacs 内置的 SQLite，不依赖 emacsql 或 org-roam。文件在 `.cache/index-<哈希>.db`，每个笔记库路径一个，验证时指向临时笔记库不会改写真实索引。
- 解析是对文件文本的直接扫描，只认标题、属性抽屉、计划行、`#+title`、`#+filetags` 和 id 链接，不启动 `org-mode`。
- 刷新是增量的：比较文件的修改时间和大小，只重读有变化的文件。不依赖文件监视，所以同步、git 或其他程序做的修改也会被发现。
- 全文检索用 FTS5 的三元组分词，按子串匹配，中文不需要分词；每个节点只收录它自己的文字，不包含嵌套在里面的其他节点。
- 图形界面、守护进程和命令行打开同一个文件，写入由 SQLite 串行化，每个写入方从同样的文件得出同样的行。

读取接口只有四个：`my/index-records`（全部节点）、`my/index-node`（按 ID）、`my/index-links`（id 链接）、`my/index-search`（全文检索）。视图、节点表、仪表盘查询块、命令行、MCP 和 AI 概览都只通过它们读节点。写入仍然只有一条路径：`my/node-call-at-id` 修改 Org 文件，然后让索引重读该文件。

索引范围是笔记库里除 `30_Library/`、`40_Archives/`、隐藏目录和同步冲突副本之外的 `.org` 文件。

org-roam 目前仍在使用的地方：交互式采集（模板来自 `types.org`）、查找和插入节点、反向链接窗口、日记命令，以及 GTD 用 org-mem 取文件列表。这些不再是数据模型的一部分，替换计划见第六节。

## 四、存储模型

笔记库是 `notes/` 下的普通 Org 文件，Org 文本是唯一权威，org-roam 数据库和命令行索引都是可以重建的索引。

内容进出笔记库的四条通道：

| 通道 | 方向 | 触发 | 会覆盖已有文件吗 | 会删除文件吗 |
|------|------|------|------------------|--------------|
| 导入 `my/storage-import` | 外部文件夹到笔记库 | 手动 | 不会 | 不会 |
| 导出 `my/storage-export` | 笔记库到外部文件夹 | 手动 | 不会，总是新建带日期的文件夹 | 不会 |
| 快照 `my/storage-snapshot` | 笔记库到快照目录 | 每天自动一次，导入前，全量同步前，或手动 | 不会 | 只删除超出保留份数的旧快照 |
| 同步 `my/sync-now` | 笔记库与云端双向 | 启动后和定时，或手动 | 会，较新的一份生效，另一份留作 `.conflict` 副本 | 会，一端删除后另一端跟着删除 |

同步是唯一会覆盖和删除的通道，所以快照独立于同步存在：误删或错误合并之后，可以从快照目录找回当天之前的版本。

导入的落点规则：

- 来源带有 `00_Roam/` 或 `.orgseq/`，说明它本身是一个 org-seq 笔记库，按层合并。
- 其他文件夹整体放进 `30_Library/<文件夹名>/`，作为参考资料，之后再由使用者整理成节点。
- 来源与笔记库有重叠时拒绝执行。

启动时的行为：创建缺失的笔记库目录，到期时做一次快照，配置了远端时做一次同步。发现未导入的 `~/NoteHQ/` 时只在回显区提示一次，不弹对话框；这条信息之后一直显示在 `my/storage-status` 和 `orgseq info` 里。

## 五、数据保护

一份笔记最多存在于三个地方：笔记库、本机快照、云端远端。

| 情况 | 能恢复的来源 |
|------|--------------|
| 删除或重装了 `~/.emacs.d` | 快照目录，云端 |
| 同步把误删带到了本机 | 快照目录 |
| 导入或合并的结果不对 | 操作前自动生成的快照 |
| 磁盘损坏或设备丢失 | 只有云端 |

最后一行是这套方案的边界：快照和笔记库在同一块磁盘上，没有配置同步时，磁盘损坏会同时丢掉两者。`M-x my/doctor` 的 “Library copies” 检查在既没有远端也没有快照时给出警告，但有快照而没有远端时判为通过。

查看状态的入口是同一个函数 `my/storage-info`：图形界面 `SPC n S t`，命令行 `orgseq info`，自检 `orgseq doctor`。

## 六、尚未实现

按先后顺序：

1. 用内核命令替换剩下的 org-roam 用法。查找节点、插入链接、反向链接列表可以直接建立在索引上；采集和日记需要自己的模板展开。做完之后 `init-roam` 才能真正关掉。现在把它加进 `my/init-disabled-modules` 会让采集和 `SPC n` 下的若干命令失效。
2. 模块自带声明，加载顺序由依赖计算。现在目录已经分组，但顺序仍是 `init.el` 里手写的列表加 `my/init-module-requires`。
3. 数据模型扩充：类型自带默认视图（等同于 Notion 的数据库页面）、每个类型多个记录模板、汇总字段和公式字段。
4. 交互层：统一的命令面板、Org 缓冲区里的 `/` 插入菜单、节点标题下的字段面板。
5. 从快照整体恢复。现在只能把快照当作文件夹导入（只补回缺失的文件），或手动复制。
6. 不依赖源码仓库的安装和升级：带版本号的发布包和 `orgseq upgrade`。
7. 首次启动的引导页，显示存储状态和下一步。
8. Windows 和 macOS 的验证。`deploy.ps1`、`scripts/check.ps1`、`bin/orgseq.cmd` 已按新目录修改，但没有运行过；`deploy.ps1` 仍然备份整个目录。
9. 真实网盘上的同步验证。同步逻辑只用本地目录充当远端测试过。
10. 文档里残留的 `~/NoteHQ/` 说法（`GUIDE.md`、`TUTORIAL.md`、`WORKFLOW.md`），以及 README 模块表按新目录重写。

## 七、需要确认的取舍

以下是实现时做的选择，可以改：

- 快照放在 Emacs 目录之外。好处是删掉 `~/.emacs.d` 不会连快照一起丢；代价是“所有东西都在软件目录里”这一点有了一个例外。
- 快照保留 10 份，每天最多自动做 1 份，并且只在笔记库有改动的日子做。
- 普通文件夹导入到 `30_Library/`，而不是 `00_Roam/`。理由是没有 Org ID 的文件不是节点，放进原子笔记层会让那一层变乱。
- 导入从不覆盖。同名文件以笔记库里的为准，来源里的版本被跳过，不生成冲突副本。
- 笔记库位置仍然是一个可定制变量（`my/note-home`），只是不在任何界面里要求设置。
- 索引范围沿用之前的做法，不收录 `30_Library/` 和 `40_Archives/`。导入到 `30_Library/` 的普通文件夹因此不会出现在视图和检索里，直到整理进其他层。
- 模块文件保留 `init-*.el` 的名字，只移动了目录，没有改成 Doom 那样每个模块一个子目录。
