# org-seq Architecture Optimization Design

Date: 2026-07-13

## Status

Approved by the user's standing request to continue optimizing the project. The
implementation remains subject to the repository validation and no-automatic-
commit rules.

## Objective

Improve org-seq by adapting proven ideas from Doom Emacs, Spacemacs, LazyVim,
the GNU Emacs manuals, and documented community experience without turning the
repository into a general-purpose Emacs distribution.

The finished configuration must remain:

- a deployable Emacs 30+ configuration;
- Windows-first, with Linux and macOS support at platform boundaries;
- based on `package.el`, `package-vc-install`, and built-in `use-package`;
- explicit about failures and external dependencies;
- compatible with the existing `custom.el` override layer;
- independent of EAF and backed by Ghostel for terminal workflows;
- testable without committing generated bytecode or changing user data.

## Sources And Adaptation Policy

### Doom Emacs

Adopt the following MIT-licensed design ideas:

- module load records with timing and failure context;
- a doctor command with actionable, module-aware checks;
- centralized popup policy;
- small, inspectable core interfaces instead of scattered conventions.

Do not import Doom's package manager, `doom!`, `map!`, `use-package!`, profile
loader, autoload generator, or full popup DSL. Small source-derived fragments
may be used only after dependency review and must be recorded in
`THIRD_PARTY.md`.

### Spacemacs

Reimplement, rather than copy, these GPL-covered ideas:

- mnemonic leader-key namespaces;
- explicit module documentation and dependency descriptions;
- repeatable transient workflows for related commands;
- local-leader consistency across related major modes.

The configuration-layer engine, EIEIO package objects, package ownership, and
dependency solver are out of scope. This avoids both GPL code incorporation and
the compatibility burden observed in the Spacemacs layer core.

### LazyVim

Translate these Apache-2.0/Lua design ideas into native Elisp conventions:

- data-first metadata for modules and checks;
- explicit conditional activation;
- defaults followed by a documented user override layer;
- optional feature groups only when real usage justifies them;
- descriptions as first-class keybinding metadata.

Do not translate Lua line by line and do not introduce implicit deep-merge
semantics. Community reports show that implicit plugin and keymap merging can
make final configuration ownership difficult to understand.

### GNU Emacs

Prefer built-in mechanisms over donor-specific compatibility layers:

- `use-package` autoload triggers such as `:commands`, `:hook`, and `:bind`;
- `display-buffer-alist` and action alists for popup placement;
- `define-obsolete-function-alias` and
  `define-obsolete-variable-alias` for migrations;
- ERT, batch byte compilation, and batch startup checks for validation.

## Non-Goals

- No general profile or layer dependency solver.
- No replacement for `package.el`.
- No automatic major-version dependency upgrades.
- No automatic system, PATH, registry, proxy, or shell-profile modification.
- No network access from diagnostics.
- No EAF compatibility shim.
- No rewriting stable PKM, GTD, capture, or research behavior unrelated to a
  measured problem.
- No license change unless GPL source is deliberately copied later.

## Architecture

The work is split into four independently verifiable subprojects. Each
subproject must leave the configuration usable and must receive its own focused
tests before the next one starts.

### Subproject 1: Core Diagnostics And Verification

#### Module records

Keep the fixed module order in `init.el`. `init-doctor` is the first guarded
module so its commands remain available when later modules fail; its own load
result becomes visible after it loads. Extend the guarded loader to record a
result for every attempted module:

- module symbol;
- state: `loaded` or `failed`;
- elapsed seconds;
- captured error object when failed.

The loader continues attempting later modules after a failure. It does not
silently skip a dependent module and does not add dependency resolution.
`my/--init-errors` and `M-x my/init-errors` remain supported.

#### Doctor

Add `lisp/init-doctor.el` with a pure result-producing layer and a presentation
layer.

Each check returns a plist with these fields:

- `:id` -- stable symbol;
- `:label` -- short ASCII description;
- `:status` -- `pass`, `warn`, or `fail`;
- `:detail` -- observed state, without secrets;
- `:remedy` -- actionable next step or nil.

`my/doctor-run` returns the complete list. `M-x my/doctor` renders it in a
read-only special-mode buffer. Checks cover:

- Emacs 30+ and SQLite availability;
- the configured NoteHQ paths;
- module load failures;
- required or optional executables (`git`, `rg`, `fd`/`fdfind`, `pwsh`,
  `yazi`, and configured AI CLIs);
- Ghostel package availability and native-module readiness when inspectable
  without downloading;
- key packages used by active modules.

Missing optional tools produce warnings. Missing requirements that prevent a
documented core workflow produce failures. The doctor never installs packages,
downloads modules, creates directories, or mutates user configuration.

`M-x my/init-report` renders module state and timing separately from the broader
doctor report.

#### Validation runner

Add `scripts/check.ps1` as the canonical Windows validation entry point. It:

- locates Emacs without modifying PATH;
- runs focused ERT files;
- byte-compiles root, module, and bundled-package Elisp with the documented
  load paths;
- runs `emacs --batch -Q -l init.el`;
- records every native process exit code;
- removes generated `.elc` files in `finally`;
- returns a non-zero process exit code when a required check fails;
- emits a concise object-based summary of passed, failed, warnings, and cleanup
  state.

The Bash deployment path retains equivalent documented commands; a separate
shell runner is added only if repeated Linux/macOS validation shows a need.

### Subproject 2: Popup, Keymap, And Startup Governance

#### Popup registry

Create one org-seq-owned popup registry implemented with
`display-buffer-alist`. A rule declares a buffer matcher, side, size, selection
behavior, slot, and dedication policy. Registration must be idempotent and
must not delete unrelated user rules.

Ghostel terminal, AI CLI, Yazi, compilation, help, and query buffers use the
registry where their workflows require stable placement. The existing
`my/cli-popup-*` API remains the terminal lifecycle boundary.

The first version intentionally omits Doom-specific TTL and quit-policy
machinery. Those features are added only if a concrete workflow requires them.

#### Keymap verification

Retain `general.el` and the existing leader definitions in `init-evil.el`.
Define a small registry of top-level prefix names and a focused set of critical
binding expectations. ERT verifies that:

- every documented top-level prefix has a which-key description;
- critical Ghostel, PKM, GTD, file, and help bindings resolve to the documented
  commands;
- removed EAF commands do not remain bound;
- documented commands are interactive when their modules load successfully.

Avoid a new `map!`-style DSL.

#### Startup measurement

Use the module timing records before changing lazy-loading behavior. Numeric
`:defer` values and idle timers are reviewed individually:

- replace them with `:commands`, `:hook`, `:mode`, or explicit after-init work
  when behavior remains equivalent;
- retain a timer when delayed background initialization is the actual feature;
- do not trade deterministic readiness for a cosmetic startup number.

Record before/after startup and module timings on the same machine and Emacs
build. Do not publish unmeasured performance claims.

### Subproject 3: Package And Override Governance

#### VC package inventory

Centralize metadata for Git-hosted packages currently bootstrapped in multiple
modules while leaving package-specific configuration in its owning module.
The inventory records package symbol, URL, owning module, and optional status.

Installation remains compatible with the existing interactive first-run
workflow. Noninteractive validation never performs network installation.

Add a read-only package audit to the doctor. Do not introduce a lockfile or pin
unversioned GitHub packages unless the user requests reproducible pinning.

#### User override contract

Keep `custom.el` as the explicit user override layer loaded before modules.
Add documented before/after module-load hooks only where they solve a real
extension need. Final values must be inspectable; do not implement implicit
deep merging or hidden per-module override files.

Use obsolete aliases and warnings for renamed public customization variables.
Do not silently ignore old names.

### Subproject 4: Documentation, Provenance, And Completion Audit

Add `THIRD_PARTY.md` containing every directly reused source fragment, upstream
URL, original license, local file, and adaptation note. Design-only inspiration
is listed separately from copied code.

Synchronize:

- `README.md` for user-visible commands and dependencies;
- `CONTRIBUTING.md` and `AGENTS.md` for load order and validation;
- `doc/GUIDE.md` or a focused architecture document for extension contracts;
- Ghostel/EAF migration documentation already changed in the current worktree.

The final audit compares every requirement in this document with authoritative
evidence from source files, ERT output, compile output, startup output, and Git
diff/status. Passing a narrow test cannot prove a broader requirement.

## Error Handling

- Module errors remain captured as original error objects and are formatted
  only at presentation time.
- Doctor predicates catch their own inspection failures and return `warn` or
  `fail` records rather than aborting the whole report.
- Missing optional executables never cause startup failure.
- Validation scripts stop treating a command as successful when its process
  exit code is non-zero, even if output text looks normal.
- No diagnostic output includes environment values, tokens, authentication
  files, command histories, or note contents.

## Testing Strategy

Every behavioral change follows red-green-refactor:

1. Add one focused ERT test.
2. Run it and confirm failure for the missing behavior.
3. Add the minimal implementation.
4. Run the focused test and relevant regression tests.
5. Byte-compile changed Elisp.
6. Review the diff before proceeding.

Required suites include:

- module result and timing behavior;
- doctor status classification and rendering-independent results;
- popup rule registration and idempotence;
- critical leader-key resolution;
- Ghostel terminal and Yazi lifecycle regression tests;
- VC package audit behavior without network access;
- batch startup and full-repository byte compilation.

## Completion Criteria

The optimization is complete only when all of the following have current
evidence:

1. Ghostel is the sole integrated terminal backend and no EAF runtime or docs
   remain.
2. Every configured module has an observable load result and timing.
3. `my/doctor` reports actionable, non-mutating platform and dependency state.
4. Popup placement is centralized without overwriting unrelated user rules.
5. Critical documented leader keys pass automated resolution checks.
6. Numeric deferred loads and idle timers have documented, reviewed reasons or
   have been replaced by deterministic autoload triggers.
7. Git-hosted packages have recorded ownership and source metadata.
8. User overrides remain explicit and backward-compatible.
9. Focused ERT, full byte compilation, and batch startup pass on an environment
   that contains Emacs 30+ and the required dependencies.
10. Validation leaves no tracked or untracked `.elc` files.
11. Documentation, load-order comments, and runtime behavior agree.
12. The final Git diff contains no unrelated formatting, generated artifacts,
    credentials, or unintended user-file changes.

## License Decision

Keep the repository under MIT for this program of work. Use Doom code only when
it is independently useful and attribution is preserved. Reimplement Spacemacs
ideas without copying GPL source. Translate LazyVim architecture rather than
copying Lua. Reconsider GPL-3.0-or-later only if a future approved change
deliberately incorporates Spacemacs implementation code.
