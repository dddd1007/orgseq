# org-seq

A modular Emacs configuration for personal knowledge management, built on its own Org node index with Zettelkasten methodology.

Platforms: **Linux** is the primary target (P0). Windows and macOS are supported at P1: their scripts are kept consistent but are validated less often.

## Prerequisites

- **Emacs 30+** (required for built-in SQLite, use-package, and which-key)
  - Emacs 31.1 is supported; see [doc/EMACS_31.md](doc/EMACS_31.md) for the
    compatibility and package follow-up audit.
  - Windows: official GNU build from https://ftp.gnu.org/gnu/emacs/windows/ (native-comp is optional)
  - Verify: `M-: (sqlite-available-p)` must return `t`
- **ripgrep** (`rg`): recommended for consult-ripgrep
- **fd**: recommended for consult-find (`fdfind` on Debian/Ubuntu is also supported)
- **git**: required for magit
- **yazi**: optional external TUI file picker for `SPC o y` / `SPC o Y`
- **Fonts** (optional but recommended):
  - [Cascadia Code](https://github.com/microsoft/cascadia-code) (Latin monospace)
  - [Inter](https://rsms.me/inter/) (Latin proportional text in Org, sidebars,
    and dashboards; Segoe UI and other system sans fonts are the fallback)
  - [LXGW WenKai Mono](https://github.com/lxgw/LxgwWenKai) (CJK)

## Diagnostics

- `M-x my/doctor` checks Emacs, SQLite, NoteHQ paths, module failures,
  Ghostel Elisp/native readiness, package load health, configured shells, and
  optional tools without changing the system or downloading anything.
- `M-x my/init-report` shows whether each module loaded and how long it took.
- `M-x my/keymap-audit` verifies the effective critical SPC bindings.
- `M-x my/vc-package-audit` shows Git package status, source, and owner module.
- On Windows, run the complete contributor validation suite with:

  ```powershell
  pwsh -NoLogo -NoProfile -File scripts/check.ps1
  ```

  The script requires PowerShell 7 and Emacs 30+, automatically finds standard
  Program Files installations, isolates NoteHQ writes to a temporary directory,
  and removes generated bytecode.
  Missing runtime and optional dependencies are reported as warnings so a clean
  source checkout can be checked without network access. After deployment, use
  the strict readiness gate:

  ```powershell
  pwsh -NoLogo -NoProfile -File scripts/check.ps1 `
    -PackageUserDir "$HOME\.emacs.d\elpa" `
    -RequireAllModules -RequireDependencies
  ```

  Strict mode fails on guarded module errors, keymap drift, or required doctor failures.
  Add `-RequireNoWarnings` to also fail on byte-compilation warnings; the tree
  is expected to compile warning-free on Emacs 30 and 31.

  The runner compiles into a temporary directory, so a check never writes
  bytecode into the working tree and two runs (for example one per Emacs
  version) can share a checkout. It also byte-compiles a staged copy and runs
  the startup, module, and keymap audits against that compiled copy, because
  deployment byte-compiles the target and some defects only appear there.

## Quick Start

1. Clone this repo:
   ```bash
   git clone <repo-url> ~/CodeProject/org-seq
   cd ~/CodeProject/org-seq
   ```

2. Run the deploy script (checks prerequisites, backs up existing config, deploys):

   PowerShell (Windows):
   ```powershell
   .\deploy.ps1
   ```

   Bash (Linux/macOS):
   ```bash
   ./deploy.sh
   ```

   Options: `-NoBackup` / `--no-backup`, `-Force` / `--force`, `-SkipChecks` / `--skip-checks`, `-Target DIR` / `--target DIR`
   PowerShell also supports `-WhatIf` for a dry run.

   A deployment replaces only `early-init.el`, `init.el`, `ec`, `core/`,
   `kernel/`, `modules/`, `packages/` and `bin/`. The note library
   (`notes/`), your own files in `user/` (`custom.el`, `modules.el`,
   `config.el`) and the installed packages are never overwritten; a
   `custom.el` from an earlier version is moved into `user/` once.
   `deploy.sh` backs up the files it replaces plus `user/`; `--full-backup` copies the whole directory
   instead. `deploy.ps1` still copies the whole directory.

   After the first deployment, update with `orgseq upgrade` (Linux and macOS;
   `orgseq upgrade --check` only reports): it redeploys from the checkout or
   remote recorded in `.org-seq-source`, so the source repository need not be
   kept around. `orgseq version` prints what is installed.

   Both deployers refuse filesystem roots, the home directory, and the source
   tree or any of its ancestors as targets. A deployment is reported complete
   only after byte compilation succeeds; verification failures exit nonzero
   and leave the timestamped pre-deployment backup available for rollback.

3. Launch Emacs — packages will auto-install on first run (needs internet).
   Startup opens Today's capture-ready Daily Workspace with a read-only
   14-calendar-day sidebar. The Dashboard remains available at `SPC l d`.

   The note library (still called NoteHQ in these docs) is created
   automatically in `notes/` under the Emacs directory, for example
   `~/.emacs.d/notes/`. No folder has to be chosen and nothing is asked at
   startup. Notes kept elsewhere, an older `~/NoteHQ/` included, come in with
   `SPC n S i` (`my/storage-import`), which copies and never modifies the
   source. See [Storage and sync](#storage-and-sync) for snapshots and for
   sharing the library between devices. `ORG_SEQ_NOTE_HOME` still overrides the location and is what the
   validation scripts use to isolate writes.

4. Post-install:
   ```
   M-x nerd-icons-install-fonts
   ```
   Windows may require right-clicking the downloaded `.ttf` files and selecting "Install".
   macOS may ask you to confirm the install in Font Book.


### Storage and sync

The library is a directory of plain Org files at one fixed place inside the
Emacs directory. Everything else moves copies in or out of it:

- **Import** (`SPC n S i`, `orgseq import DIR`) copies a folder in. A folder
  laid out like a library is merged layer by layer; any other folder becomes
  a subfolder of `30_Library/`. Existing files are never overwritten and the
  source is never modified.
- **Export** (`SPC n S e`, `orgseq export DIR`) copies the whole library into
  a new dated folder.
- **Snapshots** (`SPC n S b`, `orgseq snapshot`) are dated copies kept outside
  the Emacs directory (`~/.local/share/org-seq/snapshots/` on Linux,
  `%LOCALAPPDATA%\org-seq\snapshots` on Windows,
  `~/Library/Application Support/org-seq/snapshots` on macOS). One is taken
  automatically on a day when the library changed, and before every import
  and every full comparison with the remote; the newest
  `my/storage-snapshot-keep` (default 10) are kept.
- **Restore** (`my/storage-restore`, suggested binding `SPC n S R`;
  `orgseq snapshots` and `orgseq restore NAME --yes`) returns the whole
  library to the state of one snapshot: its files overwrite the library,
  library files the snapshot lacks are deleted, and empty folders are
  removed. `org-roam.db`, `.git/`, bytecode, lock and backup files are left
  alone. A snapshot of the current library is taken first (and the restore
  stops if that fails), so a restore can be undone by restoring that
  snapshot. Restored files get the current modification time, so the remote
  copy does not overwrite them at the next sync; with a remote configured
  the next sync carries the restored state, deletions included, to it, so
  run `my/sync-preview` first.
- **Sync** shares the library between devices, as described below.

`SPC n S t` (`my/storage-status`) shows the location, size, sync state and
snapshots; `M-x my/doctor` warns when the library exists in one place only.

Devices share the library through a cloud remote; [rclone](https://rclone.org) is the
sync engine, so WebDAV (Nextcloud, Jianguoyun, ...), OneDrive and Google Drive
all work the same way.

1. Install rclone (`pacman -S rclone`, `brew install rclone`,
   `winget install Rclone.Rclone`).
2. `SPC n S c` (`my/sync-setup`): pick the provider, sign in (OneDrive and
   Google Drive open a browser; WebDAV asks for URL, user and password), and
   name a folder on the remote. Credentials are stored by rclone, not by
   org-seq.
3. The first sync merges both sides and deletes nothing. After that the
   library syncs shortly after startup and every `my/sync-auto-interval`
   minutes (default 15), or on demand with `SPC n S s`.

| Key | Action |
|-----|--------|
| `SPC n S s` | Sync now |
| `SPC n S p` | Preview what a sync would change |
| `SPC n S c` | Set up or change the remote |
| `SPC n S l` | Show the sync log |
| `SPC n S x` | List conflict copies |
| `SPC n S i` | Import notes from a folder |
| `SPC n S e` | Export the library to a folder |
| `SPC n S b` / `SPC n S B` | Take a snapshot now / browse snapshots |
| `SPC n S t` | Storage status |

The sync unit is a whole file. When two devices changed the same file, the
newer version wins and the other is kept next to it with a `.conflict` suffix
for you to compare. The node index is a local cache: it is not synced
and is refreshed after a sync brings changes in. Close a note on one device
before editing it on another to avoid conflict copies.

### Views

A view is a query plus a layout over your nodes, as in Notion or Tana. It
holds no data of its own: editing a cell or moving a card changes the note's
Org file.

- `SPC # v` opens the view of a type; `SPC n v o` opens a saved view;
  `SPC n v n` creates one.
- Three layouts, switched with `v`: **table** (a row per node, a column per
  field), **list** (one compact line per node), **board** (a column per value
  of the group field; `H` / `L` move the card and set that field, or the TODO
  state when grouped by `@todo`).
- In a view: `RET` open, `o` open in another window, `e` edit the field under
  the cursor, `t` set TODO state, `+` new node (gets the view's type, the
  values its filter requires and the group at point), `/` quick filter,
  `G` group by, `s` sort, `F` filter, `c` columns, `w` save, `g` refresh.
- Filters are small expressions: `(type "reading")`, `(tag "draft")`,
  `(field "YEAR" > 2020)`, `(field "TOPIC" = current)`, `(todo "NEXT")`,
  `(modified-within 7)`, `(created-within 7)`, `(links-to ID)`,
  `(linked-from ID)`, `(under ID)`, `(title "x")`, `(text "x")`, combined with
  `and`, `or`, `not`.
- Columns can be fields, multi-hop paths (`TOPIC.AREA` follows the link in
  `TOPIC` and reads `AREA` there), reverse relations (`<-reading`: reading
  nodes that link here), and `@title @todo @tags @modified @created @in @out`.
- Saved views live in `.orgseq/views.org` in the library (`SPC n v e`), one
  heading per view, so they sync with your notes.
- Embed a view in any note with a dynamic block; `current` is the note the
  block sits in:

  ```org
  #+BEGIN: orgseq-view :type "material" :filter (field "COURSE" = current) :layout list
  #+END:
  ```

### Command line and MCP

`bin/orgseq` drives the same library without opening Emacs, in the manner of
`doom`. Add `~/.emacs.d/bin` to `PATH`.

```bash
orgseq add "A paper" --type reading --field YEAR=2024   # new note
orgseq daily "idea worth keeping"                        # append to today's Daily
orgseq search attachment                                 # titles and text
orgseq query --type reading --group STATUS --columns YEAR,AUTHORS
orgseq show ID          orgseq set ID STATUS read        # read and edit a node
orgseq sync             orgseq doctor       orgseq update
orgseq help                                              # everything else
```

Add `--json` for machine-readable output. `orgseq mcp` serves the Model
Context Protocol over stdio, so AI tools can search, read, create and edit
notes, run views, sync, and run the self-check. For Claude Code:

```bash
claude mcp add org-seq -- ~/.emacs.d/bin/orgseq mcp
```

Each call starts a batch Emacs (about three seconds). The command line keeps
its own node index in `.cache/` and rebuilds it from the Org files, so it
never competes with a running Emacs for the index; notes it
changes show up in a running Emacs when the buffer reverts.

### Node types

Notes are nodes: every file or heading with an Org ID. org-seq reads them from
its own index (`kernel/orgseq-index.el`) and adds types, fields, and table views
on top of it (`modules/notes/init-nodes.el`) without a second database. Supertag and TextUI were removed on 2026-10-22, org-roam on 2026-11-12.

- Types are defined in `~/NoteHQ/.orgseq/types.org` (`SPC # T`). Each level-1
  heading is one type; its properties `TYPE_TAG`, `TYPE_KEY`, and
  `TYPE_FIELDS` name the Org tag, the capture key, and the fields, and
  `NAME_ALL` lists allowed values for field `NAME`. A field written
  `NAME:node` holds an `[[id:]]` link to another node; `NAME:date`,
  `NAME:number` and `NAME:check` pick a matching input. `TYPE_EXTENDS` names
  one parent type whose fields are inherited, and a view of the parent type
  also lists the child type's nodes. The heading body is the
  capture template. A starter file with Reading, Concept, and Person types is
  created automatically; saving the file reloads the types.
- Applying a type (`SPC # t`) adds its tag to the node and empty properties
  for its fields. Fields are ordinary Org properties (`SPC # f`). A node is
  an instance of one type by default (`my/node-single-type`): applying a
  second type offers to replace the first, and field values always stay.
- Org text is the only authority. The node index is disposable;
  `M-x my/index-rebuild` (or `orgseq reindex`) recreates it at any time.

See [the node model](doc/NOTES_ARCHITECTURE.md#四节点模型与权威边界) (Chinese).

## Server Mode

org-seq uses a named Emacs server (`org-seq`) so you can start the daemon once and open instant client frames. Windows uses TCP auth files; Linux and macOS use the normal local socket.

### Windows tray daemon manager

A PowerShell tray app manages the daemon lifecycle:

```powershell
# Launch directly without leaving a console window
pwsh.exe -WindowStyle Hidden -NoProfile -ExecutionPolicy Bypass -File scripts\emacs-server-tray.ps1
```

The tray icon provides:
- **Double-click** — open a new emacsclient frame
- **Right-click menu** — New Frame, Server Status (PID + uptime), Restart Server, Stop & Quit, Auto-start toggle

The "Auto-start on login" option creates a shortcut in `shell:startup` so the daemon starts automatically when you log in to Windows.

### Quick client shortcuts

Windows:

```cmd
ec.cmd                 # open a new frame
ec.cmd path\to\file    # open file in existing server
```

Linux/macOS after `./deploy.sh`:

```bash
~/.emacs.d/ec                 # open a new frame
~/.emacs.d/ec path/to/file    # open file in existing server
~/.emacs.d/ec --tty file.org  # open a terminal client
```

The Unix `ec` helper starts `emacs --daemon=org-seq` if the named server is not already running, then connects with `emacsclient -s org-seq`. Set `ORG_SEQ_CLIENT=tty` to make terminal clients the default for shell aliases.

### Manual server control

If you prefer not to use the tray app:

```elisp
;; Start server inside a running Emacs:
M-x server-start

;; Or from command line:
emacs --daemon=org-seq

;; Windows:
emacsclientw -c -n -f ~/.emacs.d/server/org-seq

;; Linux/macOS:
emacsclient -c -n -s org-seq
emacsclient -t -s org-seq
```

## Key Bindings

Leader key is `SPC` in normal/visual mode, `M-SPC` in insert mode. Press `SPC` and wait for the which-key popup to see all available keys.

The leader map follows three ergonomic rules:

1. **Groups are nouns**: `n` notes, `t` tasks, `a` AI, `f` file, `b` buffer,
   `g` git, `s` search, `u` UI toggles, `#` types & fields.
2. **Doubled key = the group's primary action**: `SPC f f` find file,
   `SPC n n` find note, `SPC t t` today's tasks, `SPC g g` git status,
   `SPC b b` switch buffer, `SPC s s` search buffer, `SPC # #` node actions.
3. **The highest-frequency actions are single top-level keys**:
   `SPC d` Daily, `SPC c` capture a note, `SPC /` search, `SPC m` menu.

### Mouse

Mouse input is a **first-class citizen**, on equal footing with the keyboard:
everything in the daily PKM/GTD loop is reachable by mouse. `init-mouse.el`
owns this layer.

| Capability | How |
|------------|-----|
| Context menus | Right-click anywhere; org notes get **Task / Note / Type & Fields** submenus (state, schedule, tags, refile, links, transclusion, node types, fields, and Org properties), the agenda gets entry actions, and Daily/GTD have their own menus |
| Clickable org elements | TODO keywords, checkboxes, priorities, timestamps, and list bullets respond to clicks (org-mouse) |
| Menu bar | Always on; the **NoteHQ** menu holds the core workflow (Daily, notes, GTD views, AI, terminal, package update/rollback). Toggle with `SPC u b` |
| Click-driven GTD/Daily | Daily sidebar dates, GTD dashboard rows, and agenda entries all open with a single left click |
| Clickable buffer tabs | The tab-line across the top of each window lists the window's buffers; click a tab to switch, click its `x` to kill. Toggle with `SPC u T` (utility/side buffers are excluded automatically) |
| Drag and drop | Drop files into org buffers to attach/link/insert; drag files out of dired to other programs; drag selected text between buffers and programs; dropped images are saved under `00_Roam/assets/` |
| Wheel / side buttons | Smooth scroll, `Shift`+wheel horizontal, side buttons back/forward, middle-click paste at point |
| Terminal mouse | Mouse and context menus also work in terminal frames |

Dashboards in `00_Roam/dashboards/` are query-only. A table is an
`orgseq-query` dynamic block; its parameters are those of `my/node-query`
(`:type`, `:where`, `:recent-days`, `:sort`, `:order`, `:limit`) plus
`:columns`:

```org
#+BEGIN: orgseq-query :type "reading" :where (("STATUS" "queued")) :columns ("AUTHORS" "YEAR") :sort "YEAR" :order desc :limit 50
#+END:
```

dashboard with `SPC n v v`, `SPC n v w`, or `SPC n v i` also refreshes it.
Results come from the node index, which covers saved files. Blocks
written for the removed Supertag package (`supertag-query`) still render for
the forms `(tag ...)`, `(property K V)`, `(recent-days N)`, and `(and ...)`.

Customize `my/cli-popup-height`, `my/powershell-command`, and the relevant `my/*-command` / `my/*-arguments` variables when a machine uses different executable names or options.

### Project-wide edit (search results batch edit)

[wgrep](https://github.com/mhayashi1121/Emacs-wgrep) lets you edit search results in place and write the changes back to every matching file, like the VS Code Search Editor or Zed's multibuffer:

1. `SPC /` to run `consult-ripgrep` across the project.
2. In the minibuffer, press `C-.` (`embark-act`) then `E` (`embark-export`) to land the matches in an editable buffer.
3. In that buffer, press `C-c C-p` to enter `wgrep` mode, then edit the matches directly (all of them, or a region).
4. Press `C-c C-c` to write the changes back to all affected files (auto-saved); `C-c C-k` to abort.

### Auto-save

Visited files are auto-saved in place every 2s of idle time (VS Code "Auto Save: afterDelay"). No `#autosave#` files are produced; the on-disk file itself is written. Toggle it off with `SPC u a`. Each note save is indexed incrementally, which re-reads only the saved file, and saving an Emacs Lisp buffer runs compile-angel's on-save byte-compilation, which is the intended behavior but happens more often with auto-save on.

## Appearance

- **Theme**: `modus-operandi` (light) and `modus-vivendi` (dark) with org-seq
  palette overrides (`my/ui-palette-light`, `my/ui-palette-dark`): a neutral
  white or near-black canvas, one indigo-violet accent for links, cursor,
  selection, and Today, headings in the body text color, 1px window dividers,
  and a 1px rule above each mode line. Set `my/ui-use-org-seq-palette` to nil
  for the stock Modus colors. `SPC u d` toggles light and dark; `SPC u t` can
  still load any other theme.
- **Fonts**: Inter is the preferred proportional font (`my/latin-vp-font-candidates`),
  with Segoe UI and other system sans fonts as fallbacks.
- **Org**: TODO states are drawn as colored badges and tags as pills (GTD
  context tags such as `@work` in blue-gray); headings show fold chevrons
  instead of bullets; the `#+title:` and `#+filetags:` keywords are hidden;
  progress cookies such as `[2/5]` are drawn as bars; the sticky header is a
  small muted breadcrumb.
- **Prose column**: Org buffers are shown in a centered column of
  `my/prose-column-width` (72) columns with `my/prose-line-spacing` (0.16) extra
  line spacing. `SPC u c` toggles the column.
- **Sidebars and menus**: the Daily sidebar, Treemacs, and imenu-list sit on a
  gray surface slightly offset from the page (`my/ui-surface`). These buffers,
  the GTD dashboard, and node table views highlight the current row and hide
  line numbers (`my/ui-surface-modes`). The Daily sidebar
  shows a filled dot for days with a note and a hollow dot for days without
  one, Today in the accent color, a gap between weeks, right-aligned dates,
  and key hints. The GTD dashboard has VIEWS, PROJECTS, and CONTEXTS sections
  with right-aligned counts.
- **Constraints**: text contrast meets WCAG 2.2 AA (body text above 15:1,
  labels at least 4.5:1, non-text marks at least 3:1); color is never the only
  cue (badges keep their keyword text, Daily dots are filled or hollow, project
  health uses glyphs with a legend).

### Package updates, snapshots, and rollback

Packages auto-update every 7 days (and manually via `SPC q u`). Because ELPA
archives only serve the latest version, org-seq snapshots the entire `elpa/`
directory to `~/.emacs.d/package-snapshots/<timestamp>/` **before every
upgrade**; if the snapshot cannot be created, the upgrade is aborted. If an
upgrade breaks something:

```
M-x my/package-snapshot-rollback
```

restores the chosen snapshot (default: the most recent) and keeps the replaced
tree as a `-replaced` snapshot so the rollback itself can be undone. Restart
Emacs after rolling back. The last `my/update-snapshot-keep` (default 2)
snapshots are retained. If archive refresh or either upgrade stage fails, the
successful-update timestamp is not advanced.

### ELPA signature checking on Windows

MSYS-built GPG binaries (the one bundled with the official Windows Emacs
build, and the one from Git for Windows) treat Windows-style `--homedir`
paths as relative paths and fail, which used to force signature checking
off unconditionally. org-seq now probes at startup for a gpg that can
actually operate on `package-gnupghome-dir` — first the one epg resolves,
then known native GnuPG install locations (`C:/Program Files (x86)/GnuPG`,
`C:/Program Files/GnuPG`). When a working gpg is found, GNU/NonGNU ELPA
signature verification stays enabled (and `epg-gpg-program` is pointed at
it if needed); only when none is found is `package-check-signature`
disabled, with a message. Install native GnuPG to enable verification:

```powershell
winget install GnuPG.GnuPG
```

Check `my/package-signature-status` to see which way startup resolved.

### Optional pyim rime-frost dictionary

org-seq can use a converted local copy of the rime-frost dictionary as a pyim dictionary. Generate or refresh it with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\update-rime-frost-pyim.ps1
```

The script requires `git` and Python 3 on `PATH`. It clones or updates `gaboolic/rime-frost` under `.cache/rime-frost`, converts the active Rime dictionary tables into pyim format, and writes `pyim/rime-frost.pyim`. The generated `pyim/` directory is local runtime state and is intentionally ignored by git; `modules/editor/init-pyim.el` loads the converted dictionary automatically when that file exists. `deploy.ps1` and `deploy.sh` copy this generated dictionary to the deployed `~/.emacs.d/pyim/` when it is present.

### Bundled subproject: `packages/org-focus-timer/`

`init-focus.el` loads a Vitamin-R-style focus timer that currently lives inside this repository at `packages/org-focus-timer/`. The deploy scripts copy the whole `packages/` tree to `~/.emacs.d/packages/` alongside `core/`, `kernel/`, and `modules/`, and `init-focus.el` resolves the load path relative to `user-emacs-directory`, so no extra configuration is needed — clone the repo, run `deploy.sh` / `deploy.ps1`, and the focus timer is available as `SPC t f` / `SPC t F` / `SPC t X`.

The package has no external dependencies beyond stock Emacs Lisp features and no org-seq-specific code inside it, which keeps it portable. When it matures, it will graduate into its own repository and `init-focus.el` will switch to referencing it via `:vc`. Until then, the source lives next to the config that calls it so iteration is fast — edit the file, `M-x eval-buffer`, and changes take effect immediately.

See `packages/org-focus-timer/README.md` for the package-level documentation.

## Notes Directory

Notes live under `my/note-home`, which defaults to `~/.emacs.d/notes/` and can be overridden with `ORG_SEQ_NOTE_HOME`. The directory is organized as a Roam + PARA hybrid:

```
~/.emacs.d/notes/
├── 00_Roam/             ← Atomic notes — flat, plus daily/, capture/, dashboards/
│   ├── daily/           ← Daily journal entries
│   ├── capture/         ← Captured notes (timestamp-prefixed)
│   └── dashboards/      ← Read-only orgseq-query views
├── 10_Outputs/          ← PARA: deliverable projects (bounded lifetime)
├── 20_Practice/         ← PARA: long-term responsibility domains
├── 30_Library/          ← PARA: reference materials
├── 40_Archives/         ← Completed/paused work
└── .orgseq/             ← Per-library config (types.org, capture-templates.el, ai-config.org)
```

The numeric prefixes (10-step gaps) exist so the sidebar sorts the layers in workflow priority order (Roam first, Archives last) instead of alphabetical-by-name order.

Classification is by **node type** (an Org tag defined in `.orgseq/types.org`), not directory — `00_Roam/` itself is flat. GTD agenda scans `00_Roam/` + `10_Outputs/` + `20_Practice/` (skips `30_Library/` and `40_Archives/`). The node index covers `00_Roam/`, `10_Outputs/`, and `20_Practice/`.

The node index is **Org-only** (Markdown files are not indexed). First-time index of existing notes: `M-x my/index-rebuild`.
